# 八维评分标准与评语指南

打分对象是**用户本人**（通过其历史消息质量），不是对面的 AI。评分 = "如果这些话
是某个模型生成的，它大概是什么水平"。0-100 分，段位由脚本自动映射，无需手填。

## 八个维度与锚点

| 维度 | key | 30 分左右 | 60 分左右 | 85 分以上 |
|---|---|---|---|---|
| 逻辑推理 | reasoning | 结论先行、不问为什么 | 能拆解问题、会追问因果 | 能发现 AI 回答里的逻辑漏洞并反驳 |
| 代码能力 | coding | 只会说"报错了"不给信息 | 贴报错+说清期望 | 给最小复现、自己先排查过、懂上下文 |
| 并发能力 | concurrency | 峰值 1 个 session 单线程 | 峰值 2-3 个 session 交替 | 峰值 ≥5 或日均 ≥4 个 session、多项目同开 |
| 知识广度 | knowledge | 话题单一 | 涉及 2-3 个领域 | 跨领域提问且用对术语 |
| 需求表达 | prompting | "帮我弄一下那个" | 能说清目标+约束 | 给背景、给示例、分点、主动澄清歧义 |
| 创造力 | creativity | 全是任务型指令 | 偶尔有玩法/花活 | 主动整活、设计有趣的东西、提刁钻角度 |
| 上下文记忆 | context | 反复重复同一需求 | 能引用几轮前的话 | 跨 session 记得之前的事，主动对齐 |
| 幽默情商 | humor | 纯工具人对话 | 偶有调侃/表情包浓度 | 会玩梗、接梗、锐评 AI 本身 |

**并发能力**直接读 `metrics.json` 的 `concurrency` 块打分（不靠主观印象）：
峰值 ≥6 或日均 ≥5 → 88+；峰值 4-5 或日均 3-4 → 72-85；峰值 2-3 → 55-70；
峰值 1 → 30 以下；单日最多项目数 ≥5 可再 +3。comment 里引用具体数字。

判分原则：
- 只认 digest 里的**证据**，没证据的维度 50 分 + comment 写"证据不足，按人类均值放水"。
- 消息里出现代码块、报错堆栈、技术术语 → coding/reasoning 的直接证据。
- 追问"为什么/不对，应该是…" → reasoning 加分证据。
- 指令里带"帮我/谢谢/继续"频率高 → prompting/沟通风格素材。
- 宁低勿高：用户是来被锐评的，全 85+ 会让报告不好笑；但单项低于 25 要有实锤。

## 型号命名公式

`Homo-{参数量}{后缀}-Preview`，参数量 = 综合分四舍五入（如 72 → 72B）。后缀按特质
选 1-2 个：

- TTFT 中位 > 60s → `-Thinking`
- prompting ≥ 75 → `-Instruct`
- 创造力 ≥ 75 → `-Creative`
- coding ≥ 80 → `-Coder`
- 夜猫子指数 > 40 → `-Nightly` ( nightly build 双关 )
- 样本 < 10 条 → `-0.5shot`

人类永远处于 Preview 阶段，不准去掉。示例：`Homo-67B-Thinking-Nightly-Preview`。

## 总评写作指南 (overall_comment)

- 150-250 字，2-4 句。结构：先给定位（综合段位一句话），再点 1-2 个最突出的
  高分维度夸，再点 1 个最低分维度损（损方法不损人），最后一条离谱的"升级建议"
  （如"建议多喝热水扩大上下文窗口"）。
- 必须至少玩一个 LLM 梗：幻觉 / 温度 / 过拟合 / 上下文窗口 / 蒸馏 / 量化 /
  思维链 / 对齐 / 灾难性遗忘。
- 语气是朋友吐槽，不是 HR 绩效面谈。禁止真的刻薄。
- 若样本 < 5 条，开头加一句："本次评测的置信度约等于掷硬币，以下内容均为基于
  X 条消息的过度泛化。"
